# 문제 해결과 현장 검증

이 안내는 현재 `feat/fork-stability` 브랜치의 구현을 기준으로 합니다.
설치와 구현 범위는 [README](../README.md), 모델별 포크 사례는 [조사 기록](fork-survey.md)을 참고하세요.
다른 설치에서 동작한 기능이 모든 코콤 모델에서 동일하게 동작하는 것은 아닙니다.

## 연결되지 않거나 재시작 후 사용할 수 없는 경우

- TCP: HA 실행 환경에서 EW11의 IP와 포트에 접근 가능한지 확인합니다. 기본 포트는 `8899`이며 실제 EW11 설정이 우선입니다.
- EW11의 시리얼 통신 설정과 RS-485 배선이 해당 월패드에 맞는지 확인합니다. 통신 설정을 임의로 바꾸기 전에 기존 값을 기록하세요.
- 직접 시리얼: 호스트에 `/dev/ttyUSB0` 또는 `/dev/serial/by-id/...`를 넣습니다. 현재 코드는 `/`로 시작하는 호스트를 시리얼로 처리하고 `9600` baud를 사용하며 포트 입력은 무시합니다.
- 시리얼 경로는 PC가 아닌 HA 실행 환경에서 보이는 경로여야 합니다. 컨테이너라면 장치 전달과 접근 권한도 확인합니다.
- 다른 프로그램이나 다른 포크가 같은 연결을 동시에 사용하는지 확인합니다. 어댑터의 다중 연결 허용 여부는 설치마다 다릅니다.

설정 화면은 입력을 저장하고, 실제 연결은 통합 로드에서 시도합니다.
초기 연결 실패는 HA의 설정 재시도 대상으로 처리합니다. 실행 중 연결 종료는 재연결을 시도합니다.
반복적으로 연결이 끊어지면 발생 시각, HA 로그, 어댑터 상태를 함께 기록하세요.

## 일부 기기 또는 엔티티가 없는 경우

조명·콘센트는 최초 등록에 켜짐 상태 패킷이 필요할 수 있습니다.
월패드에서 해당 기기를 한 번 켠 뒤 수신 로그와 HA 엔티티 생성 여부를 확인합니다.
기기 등록과 명령 제어 성공은 서로 다른 검증입니다.

엘리베이터 방향은 수신되지만 층수가 없는 설치도 있습니다.
월패드가 층 정보를 보내지 않는다면 층수 엔티티가 생기지 않는 것을 연결 장애로 단정하지 마세요.
공기질·에어컨·움직임 등도 실제 모델에서 해당 패킷이 제공되는지 먼저 확인합니다.

## 상태는 보이지만 제어가 안 되는 경우

물리 월패드에서 조작했을 때의 상태 수신과 HA에서 명령을 보냈을 때의 응답을 구분해 수집합니다.
응답 없이 HA 상태만 바뀐 것을 실물 제어 성공으로 판정하지 않습니다.
안전 관련 장치의 해제 명령을 시험 목적으로 반복하지 마세요.

- 가스밸브: 현재 켜기/끄기는 같은 프레임을 생성합니다. 잠금 해제 기능으로 해석하지 마세요.
- 엘리베이터: 현재 켜기/끄기는 같은 호출 프레임입니다. 끄기는 호출 취소가 아닙니다.
- 일괄소등: 상태 패킷 처리와 실제 소등 명령 동작을 따로 확인합니다. 일부 포크는 broadcast 응답이 없는 설치에서 개별 조명 OFF 전략을 사용합니다. 이 전략을 현재 브랜치의 기본 기능으로 반영하지는 않았습니다.
- 환기: 속도와 프리셋은 별개입니다. 포크의 특정 프리셋 바이트나 주기적 polling을 모델 근거 없이 전체 기본값으로 바꾸지 않습니다.
- 디밍: 현재 light 엔티티는 켜기/끄기만 구현합니다. 디밍 월패드라도 이 브랜치에서 밝기 조절은 지원되지 않습니다.

## 온도 조작 간격

난방 옵션 `thermostat_step`의 기본은 `auto`이며 기존 기기 속성을 유지합니다.
`1`은 난방 UI 간격만 1°C로 고정합니다. 저장 후 통합 항목을 다시 로드하며 에어컨에는 적용하지 않습니다.
현재 정수 바이트 디코딩/인코딩에서 UI 옵션만으로 0.5°C 제어를 만들 수 없습니다.
0.5°C를 지원하는 모델이라면 물리 조작 전후 패킷과 모델 정보를 확보해 별도의 인코딩 근거를 확인해야 합니다.

## 디버그 로그와 보고 자료

HA의 해당 통합 메뉴에서 디버그 로깅 기능을 사용할 수 있으면 켠 뒤 문제를 한 번 재현하고 로그를 내려받습니다.
또는 기존 `configuration.yaml`의 logger 설정에 아래 항목을 병합한 뒤 HA를 재시작합니다.
이미 logger 항목이 있으면 중복 키를 만들지 마세요.

```yaml
logger:
  logs:
    custom_components.kocom_wallpad: debug
```

수집 후 디버그 로깅을 원래 상태로 되돌립니다. 장시간 패킷 로그는 커질 수 있습니다.
공유 전 IP·호스트명·세대 식별 정보 등 개인정보를 가리고, 프레임 구조와 관련 바이트는 분석에 필요한 범위에서 보존합니다.

보고에는 다음을 포함하세요.

- HA 버전, 통합 버전/커밋, 월패드 모델과 가능한 펌웨어 정보.
- TCP/시리얼 연결 방식, 어댑터 모델과 기존 통신 설정.
- 기대 동작, 실제 동작, 재현 시각과 단계.
- 물리 월패드 조작 수신 로그와 HA 명령 송수신 로그.
- 재시작/재연결 전후 결과와 영향을 받는 기기만인지 전체 연결인지.

현재 18개 회귀 테스트는 HA shim과 로컬 TCP 검증입니다.
실제 HA 로드·업그레이드·실물 월패드 검증을 대신하지 않습니다.
