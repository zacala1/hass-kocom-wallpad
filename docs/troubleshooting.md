# 문제 해결

설치와 지원 기능은 [README](../README.md)를 참고하세요.
다른 설치에서 동작한 기능이 모든 코콤 모델에서 같게 동작하지는 않습니다.

## 연결되지 않거나 재시작 후 사용할 수 없는 경우

- TCP: HA 실행 환경에서 EW11의 IP와 포트에 접근할 수 있는지 확인합니다. 기본 포트는 `8899`이고 실제 어댑터 설정이 우선입니다.
- EW11의 시리얼 설정과 RS-485 배선이 월패드에 맞는지 확인합니다. 설정을 바꾸기 전에 기존 값을 기록하세요.
- 직접 시리얼: 호스트에 `/dev/ttyUSB0` 또는 `/dev/serial/by-id/...`를 넣습니다. `/`로 시작하는 호스트는 시리얼로 처리하고 `9600` baud를 쓰며 포트는 무시합니다.
- 시리얼 경로는 PC가 아니라 HA가 실행되는 환경에서 보여야 합니다. 컨테이너라면 장치 전달과 접근 권한도 확인합니다.
- 다른 프로그램이나 다른 포크가 같은 연결을 동시에 쓰는지 확인합니다. 어댑터가 다중 연결을 허용하는지는 설치마다 다릅니다.

통합을 추가하거나 주소를 재구성할 때 접속을 시험하고, 실패하면 "연결할 수 없습니다"를 표시합니다.
다른 프로그램이 같은 연결을 쓰고 있으면 어댑터에 따라 이 시험이 실패할 수 있습니다.
설정 후 처음 연결 실패는 HA가 재시도하고, 실행 중 끊김은 자동으로 재연결합니다.
연결이 반복해서 끊기면 발생 시각, HA 로그, 어댑터 상태를 함께 기록하세요.
주소를 바꿀 때는 통합을 지우지 말고 **재구성**을 사용하면 엔티티가 유지됩니다.

## 일부 기기나 엔티티가 없는 경우

- 조명·콘센트는 켜진 상태 패킷을 한 번 받아야 등록됩니다. 월패드에서 해당 기기를 켜 보세요.
- 엘리베이터 층수는 월패드가 층 정보를 보내는 설치에서만 나타납니다.
- 공기질·에어컨·움직임도 모델이 해당 패킷을 보내는지 먼저 확인합니다.
- 연결 직후와 HA 재시작 직후에는 조명·난방 같은 기기가 한동안 `unavailable`일 수 있습니다. 해당 기기의 새 상태 패킷을 받아야 사용 가능으로 바뀝니다.
- 가스밸브·엘리베이터·움직임 센서는 상태가 바뀔 때만 신호가 오므로, 한 번 확인된 기기는 연결되어 있는 동안 마지막 상태를 유지합니다.
  연결이 끊겼다 복구된 직후에는 다음 신호가 올 때까지 마지막 상태가 실제와 다를 수 있습니다.

## 상태는 보이지만 제어가 안 되는 경우

월패드에서 직접 조작했을 때의 수신 로그와 HA에서 명령을 보냈을 때의 응답 로그를 따로 수집하세요.
월패드가 확인 응답을 보내지 않으면 HA는 명령 실패 오류를 표시합니다.
안전과 관련된 기기의 해제 명령을 시험 삼아 반복하지 마세요.

- 가스밸브: `valve` 엔티티이며 닫기 프레임만 보냅니다. 열기는 제공하지 않고 잠금 해제 기능도 아닙니다.
  표시되는 열림/닫힘은 월패드 상태 신호를 해석한 것이므로, 실제 밸브 상태와 한 번 대조해 보세요.
- 엘리베이터: 켜기/끄기가 같은 호출 프레임입니다. 끄기는 호출 취소가 아닙니다.
- 환기: 속도와 프리셋은 별개이며, 프리셋은 수신 패킷에서 확인된 것만 나타납니다.
- 조명: 켜기/끄기만 지원합니다. 디밍 월패드여도 밝기 조절은 되지 않습니다.

## 알려진 제한

- 일괄소등: 월패드의 일괄소등 신호를 받으면 별도의 "Light Cut-off" 엔티티가 상태만 표시합니다.
  이 엔티티를 켜거나 끄면 오류가 나며, HA에서 일괄소등을 보내는 기능은 없습니다.
  이전 버전에서 일괄소등 신호로 첫 번째 방 조명 상태가 바뀌어 보이던 문제는 이 엔티티 분리로 해결되었습니다.
  일괄소등 동작은 사용 중인 설비에 영향을 줄 수 있으니 시험 전에 설치 소유자의 승인을 받으세요.
- 온도: 난방·에어컨 온도는 정수 단위로만 읽고 씁니다. `thermostat_step`은 화면 조작 간격만 바꿉니다.
  0.5°C를 지원하는 모델이라면 물리 조작 전후 패킷과 모델 정보가 있어야 별도로 지원할 수 있습니다.

## 연결은 되었는데 기기가 보이지 않는 경우

"KOCOM GATEWAY" 기기의 두 진단 엔티티로 어디가 문제인지 가릴 수 있습니다.

- **연결**: 어댑터와의 연결 상태입니다. 꺼져 있으면 주소·포트·배선부터 확인합니다.
- **마지막 수신**: 마지막으로 데이터를 받은 시각입니다(1분 단위로 갱신). 연결은 켜져 있는데 값이 비어 있거나
  오래전이라면 월패드에서 신호가 오지 않는 것입니다. RS-485 배선(A/B), 통신 속도, 어댑터 모드를 확인하세요.

## 보낸 프레임이 되돌아오는 어댑터

일부 어댑터는 자기가 보낸 프레임을 그대로 다시 수신합니다. 이 통합은 방금 보낸 프레임과 바이트가 같은 프레임을
1초 안에 받으면 에코로 보고 무시합니다. 월패드의 응답이 아니므로 명령 확인에 쓰지 않습니다.
[진단 파일](#진단-파일)의 `stats.echoed`가 0보다 크면 사용 중인 어댑터가 에코하는 것입니다.

## 진단 파일

문제를 보고할 때는 통합 항목의 메뉴(⋮)에서 **진단 다운로드**로 받은 파일을 함께 첨부해 주세요.
호스트(IP, 호스트명, 시리얼 경로)는 파일 어디에도 들어가지 않습니다.

- 연결 상태, 마지막 수신 후 경과 시간, 대기 중인 명령 수
- 인식한 기기 목록과 각 기기의 상태, 사용 가능 여부, 마지막으로 받은 프레임
- 수신 프레임 수, 체크섬 오류 수 등의 카운터와 최근 프레임 20개
- 이 통합이 해석하지 못한 프레임 종류(기기 코드와 명령별 횟수, 처음·마지막 프레임)

해석하지 못한 프레임은 새 기기나 다른 모델을 지원하는 데 가장 중요한 자료입니다.
기기가 보이지 않거나 일부 동작이 이상하면 해당 기기를 월패드에서 조작한 직후에 진단을 받아 주세요.

## 디버그 로그와 보고

HA의 해당 통합 메뉴에서 디버그 로깅을 켜고 문제를 한 번 재현한 뒤 로그를 내려받습니다.
메뉴가 없으면 기존 `configuration.yaml`의 `logger` 항목에 아래를 병합하고 HA를 재시작합니다.
이미 `logger` 항목이 있으면 중복 키를 만들지 마세요.

```yaml
logger:
  logs:
    custom_components.kocom_wallpad: debug
```

수집 후에는 디버그 로깅을 원래대로 돌리세요. 장시간 패킷 로그는 커질 수 있습니다.
공유 전에 IP·호스트명·세대 식별 정보를 가리고, 프레임 구조와 관련 바이트는 분석에 필요한 만큼 남겨 주세요.

보고에는 다음을 포함해 주세요.

- HA 버전, 통합 버전 또는 커밋, 월패드 모델과 가능하면 펌웨어
- TCP/시리얼 연결 방식, 어댑터 모델, 기존 통신 설정
- 기대 동작, 실제 동작, 재현 시각과 단계
- 월패드 조작 시 수신 로그와 HA 명령 송수신 로그
- 재시작·재연결 전후 결과, 영향받는 기기가 일부인지 전체 연결인지
